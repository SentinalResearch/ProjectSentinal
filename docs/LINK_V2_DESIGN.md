# Link v2 design: one persistent link per worker

Status: **proposal for owner review** (2026-10-24). Nothing here is
implemented. It touches pairing credentials, routing, and identity proof, so
no code changes until it is approved.

Goal: a terminal on any Machine feels like SSH to it, and the dashboard shows
every change as it happens. It also closes audit finding F7 (no protocol
version negotiation) before V1 freezes the link contract.

Already done and kept: Nagle's algorithm is off on every terminal socket
(`ffb5270`).

---

## 1. Today

```text
 Browser ══WSS══▶ Tailscale Serve ──▶ control sentinald ◀──HTTPS POST every 1 s── worker
   one socket per terminal pane            │                (heartbeat 30 s, projection batch,
   + one dashboard live socket             │                 notification intents)
                                           │ per terminal: HTTP identity proof,
                                           │ then a new WS to worker:7420
                                           ▼
                                     worker sentinald (listens on its Tailscale IP)
```

Two credentials exist per link, both created at pairing:
- **worker credential**: the worker presents it to the control (heartbeat,
  projection, refresh);
- **control credential**: generated by the worker, presented by the control
  to the worker's API (terminal proxy, output replay, identity proof).

Costs this design removes:

| Cost | Where | Today |
|---|---|---|
| Opening a terminal | identity proof + new TCP + WebSocket upgrade to the worker | ~3–4 round trips before the first byte (~0.4–0.6 s to the US VM, estimated) |
| Split View | every pane repeats that setup and keeps its own socket | 4 sockets and setups for 4 panes, 6 for 6 |
| Dashboard updates | worker batches every 1 s, over a new HTTPS request | up to 1 s + a round trip late; a slow request makes the Machine "delayed" |
| Offline detection | heartbeat every 30 s, offline after 90 s | 90 s |
| Version skew | `Envelope` requires exactly protocol 1; link HTTP has no version (F7) | the first protocol change breaks mixed versions |
| Worker exposure | each worker listens on its Tailscale IP for the control | an open port on every worker |

## 2. Proposal

```text
 Browser ══ one WSS per tab: dashboard + every terminal ══▶ control sentinald
   predictive echo for far Machines (separate step)              │ in-memory state, instant fan-out
                                                                 │
                     one persistent WSS per worker, opened BY the worker
                     channels: control · state · terminal N · bulk
                                                                 │
                                                       worker sentinald (no inbound port needed)
```

1. **The worker dials out.** Each worker keeps one WebSocket open to its
   control's existing HTTPS origin (`wss://<control>.ts.net/api/v2/link`),
   the same origin it already uses for heartbeats. It reconnects with backoff
   when it drops, and immediately when the network changes.
2. **Channels over that one link.** Every message names a channel. Opening a
   terminal is one message on an already-open link.
3. **The worker pushes.** State changes (Session, Command, Event, Metrics,
   notification intents) go out the moment they happen, with sequence
   numbers and acknowledgements, from the durable outbox that exists today.
4. **One socket per browser tab.** The PWA multiplexes the dashboard and every
   terminal pane over `wss://<control>/api/v2/stream`. Split View with 6 panes
   is 6 channels on one socket.
5. **Liveness on the link itself.** A ping every 5 s measures the round trip;
   three missed pings (15 s) mark the Machine offline. The measured round
   trip is shown in Diagnostics and used later for predictive echo.
6. **Versioned from the first message** (closes F7).

## 3. Framing

Each WebSocket binary message is one frame:

```text
+----------------+--------+----------------------+
| channel: u32 BE| type:u8| payload              |
+----------------+--------+----------------------+
```

| Limit | Value |
|---|---|
| Max frame | 256 KiB (larger is a protocol error; the link closes) |
| Terminal data chunk | ≤ 16 KiB, so a big output never blocks a keystroke for long |
| Bulk chunk | ≤ 16 KiB |
| Channels open per link | 256 (Sessions attached at once; more is refused with a clear error) |
| Handshake must complete in | 5 s |

Channel 0 is control. Control and state payloads are JSON (`serde` types in
`crates/protocol`, with fixtures and generated TypeScript as today). Terminal
data stays raw bytes.

| Channel | Type | Direction | Payload |
|---|---|---|---|
| 0 control | `HELLO` | worker → control | versions, machine ID, daemon version, capabilities, nonce |
| 0 | `WELCOME` | control → worker | chosen version, control proof, intervals |
| 0 | `PROVE` | worker → control | worker proof |
| 0 | `PING`/`PONG` | both | timestamp, for round-trip time |
| 0 | `OPEN` / `OPENED` / `CLOSE` | both | open a terminal or bulk channel; reason on close |
| 0 | `REVOKED`, `GOING_AWAY` | control → worker / both | link ends now / planned restart |
| 1 state | `CHANGES` | worker → control | outbox entries with cursors |
| 1 | `ACK` | control → worker | highest cursor stored |
| 1 | `SNAPSHOT_REQUIRED` | control → worker | as today's projection resync |
| ≥ 16 terminal | `DATA` | both | raw terminal bytes (output down, input up) |
| ≥ 16 | `RESIZE`, `SIGNAL`, `SNAPSHOT`, `CREDIT` | as named | JSON |
| ≥ 16 bulk | `DATA` + `END` | worker → control | saved output pages, exports |

## 4. Handshake, authentication, version

The link runs inside TLS to the control's MagicDNS name (certificate checked
as today, origin pinned at pairing) inside Tailscale's WireGuard tunnel.
Authentication is mutual and uses the two existing credentials. Neither
credential ever crosses the wire in clear text.

```text
worker  → control  WebSocket upgrade, Authorization: Bearer <worker credential>
                   (control authenticates the worker exactly as for heartbeats today)
worker  → control  HELLO   {"versions":[2],"machine_id":"01J…","daemon_version":"0.3.0",
                            "capabilities":["SESSIONS","PROJECTION",…],"nonce":"<32 hex>"}
control → worker   WELCOME {"version":2,"proof":"<HMAC-SHA256(control credential, worker nonce)>",
                            "nonce":"<32 hex>","ping_ms":5000}
worker  → control  PROVE   {"proof":"<HMAC-SHA256(control credential, control nonce ‖ machine_id)>"}
```

- The worker checks `WELCOME.proof` before acting on anything else, so a
  server that is not the paired control cannot drive its terminals. This
  replaces today's per-socket identity proof with one proof per link.
- The control checks `PROVE` and that `machine_id` matches the credential's
  registry row, as `prove_identity` does today.
- **Version negotiation:** `HELLO.versions` lists what the worker speaks;
  the control picks the highest it also speaks or closes with
  `{"code":"UNSUPPORTED_VERSION","supported":[2]}`. Each side supports the
  current and the previous link version, so updating the control or a
  worker first both work. Capabilities are negotiated in the same exchange.
- **Revocation** sends `REVOKED` and closes the link at once (today a revoked
  worker notices at its next heartbeat). Credential refresh moves to channel
  0 with the same two-phase commit as `control/refresh.rs`.
- **Browser stream:** authenticated by the owner cookie as every browser
  request today; channels to a worker are allowed only for the owner and
  only while that worker's link is up and proven.

## 5. Terminals over the link

```text
Browser   OPEN ch=7 {"machine":"01J…","session":42,"cols":120,"rows":40}
Control   finds the worker's link, OPEN ch=23 {"session":42,"cols":120,"rows":40}
Worker    attach (screen snapshot + live output, P0.2 resync on lag), OPENED ch=23
Worker    SNAPSHOT/DATA ch=23 → control maps 23→7 → browser
Browser   DATA ch=7 (keystrokes) → control → DATA ch=23 → worker → input audit → PTY
```

- **Authorization stays where it is.** The control authorizes the owner; the
  worker still checks capture capabilities and writes the input audit record
  before the PTY. Nothing new is trusted.
- **Open cost:** one round trip to the worker for `OPENED` plus the snapshot.
- **Fairness:** each connection has one writer with two queues. Interactive
  frames (channel 0, terminal data, state) always go before bulk frames,
  which are cut into 16 KiB pieces.
- **Flow control:** each terminal channel has a 256 KiB credit window; the
  receiver returns `CREDIT` as it drains. A viewer that cannot keep up gets
  the P0.2 redraw instead of an unbounded queue.
- TCP still has head-of-line blocking across channels; with 16 KiB chunks
  the worst case is one chunk's transmit time. A UDP transport
  (QUIC/WebTransport) can carry the same frames later without redesign.

## 6. State over the link

- The worker's projection and notification outboxes stay durable in SQLite
  with their existing cursors. New entries are sent immediately (coalesced
  within 50 ms), not every second.
- The control acknowledges the highest cursor it has stored; the worker
  compacts after `ACK`. On reconnect the worker resends from the last
  acknowledged cursor; the control already ignores duplicates by cursor.
- Metrics: every 2 s while any dashboard is open (the control tells the
  worker on channel 0), every 30 s otherwise. A quiet Machine stays LIVE
  because liveness now comes from the link's pings, not from uploads.
- The control applies changes to its in-memory view first, fans out to
  browsers, and writes SQLite in batches (≤ 250 ms). The browser sees the
  change one link round trip after it happened.

## 7. Failure behaviour

| Event | Result |
|---|---|
| Link drops (network change, sleep) | Worker reconnects at once, then with backoff (1 s → 30 s). Open terminals show "Reconnecting…" and re-attach with a snapshot. State resumes from the last cursor. |
| Control restarts | Sends `GOING_AWAY`; workers reconnect when it is back. |
| Worker restarts | Same; its keepers (R1) keep terminals alive underneath. |
| No pong for 15 s | Machine shown offline; its terminal channels close with a reason. |
| Unsupported version | Clear error on both sides and in Diagnostics ("Worker 0.2.4 speaks link 1; this control needs 2. Update the worker."). |
| Revoked | `REVOKED`, link closed, worker shows `REVOKED` in `sentinal connection status`. |

## 8. Rollout and compatibility

1. **0.3.0 control** accepts link v2 *and* keeps every v1 endpoint and the
   current proxy path. A v1 worker works exactly as today.
2. **0.3.0 worker** tries `/api/v2/link`. If the control answers 404 (older
   control), it uses v1 as today.
3. The PWA uses `/api/v2/stream` when the control offers it, otherwise the
   current sockets. The control serves its own matching PWA, so this is
   always consistent.
4. Once every worker is on v2 (the Machines tab shows each one's link
   version), a setting lets workers stop listening on their Tailscale IP
   (loopback only). Default stays as today until you turn it on.
5. Link v1 is removed one minor release after v2 ships.

No new dependency: the daemon already has a WebSocket server (axum) and
client (tokio-tungstenite), `hmac`/`sha2`, and the outbox store.

## 9. Tests

- Pure: frame codec (limits, oversize, unknown type, channel range),
  handshake state machine (wrong proof either side, wrong machine ID,
  version negotiation including no overlap, timeout), scheduler (interactive
  before bulk, chunking), credit window, cursor resume and duplicate
  suppression.
- In-process: control and worker over a real loopback WebSocket with a
  `FakePty`: open terminal, typing reaches the PTY once and is audited,
  6 channels on one browser stream, revocation closes the link, reconnect
  resumes state without duplicates.
- Mixed versions: v2 worker ↔ v1 control and v1 worker ↔ v2 control both
  work.
- Playwright (real control + two workers, as the existing e2e chain):
  Split View with 6 panes opens one browser socket; Diagnostics shows link
  round trips; kill a worker's network for 20 s → offline, then back.
- Security: no credential in any frame, log, or URL; terminal bytes never in
  logs; a forged `WELCOME` is refused before any terminal frame is handled.
