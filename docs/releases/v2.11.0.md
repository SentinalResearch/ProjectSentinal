# Sentinal 2.11.0

The biggest release since 2.10.0: a quieter look on every screen, an island
that is also the search, terminals you can end and clear, and AI agents that
tell you what they are doing and how far along they are.

## Before you update

1. **Back up each Machine first.** Rolling back to 2.10.0 after 2.11.0 has
   run is not safe without it: 2.10.0 reads stored rows strictly and fails on
   the new kinds of data 2.11.0 writes (TASKS X15). To roll back, restore
   this backup onto a fresh 2.10.0 install.

   ```sh
   sentinal backup create
   ```

2. **Update the control first, then the workers.** 2.11.0 workers send
   values a 2.10.0 control does not know (new agent names, longer answer
   labels). Mixed versions work in that order. A worker still on an older
   0.2.x release updates the same way.
3. Live FULL terminals are interrupted by the daemon restart, as in every
   update until Reliability R1.

## New

### A quieter Sentinal
- Light grey and black with thin numbers, line icons and pill buttons, plus
  a light / dark / auto choice in the places menu.
- **The island is the search.** Click it, press `/` or `⌘K`. It shows what
  needs you as dots, answers a yes/no question from any page, and shows the
  running job closest to done. Going back lives in the island too ("‹
  Overview", `⌘[`).
- The dashboard is one big number for what needs you, a device line that
  scopes the page to a Machine, and plain lists for each Machine.
- A startup screen checks the server and your sign-in before anything else.
- The phone is redesigned in the same style: swipe a finished terminal to
  Done, an inbox in the island, and the session page with End terminal.

### Ending, clearing and notifications
- **End terminal** sends Ctrl-C, then closes the shell (confirmed first).
- A **Done** section with Open, Hide and Delete. **Auto-clear** after 1 hour
  or 1 day hides finished terminals; it never deletes anything and never
  hides a failure you have not opened. **Keep forever** pins one.
- Hide, restore and permanently delete any finished Session; a Hidden
  Sessions page.
- An **inbox** in the island, with Needs you / Done and Mark all read. A new
  notification pops up for 6 seconds; hover holds it.

### AI agents
- **Questions read from the screen.** Claude Code, Codex, Gemini, Aider,
  Vibe and Antigravity menus show in full, with their answers, on the
  dashboard and the phone.
- **Agents report themselves** from inside a Sentinal terminal:

  ```sh
  sentinal agent-state --status working --task "migrate tests" --step 3 --of 8 --eta 12m
  ```

  It is accepted only from a process inside that terminal; the OS says
  who is calling. Scripts can print `::sentinal task name=… step=3 steps=8`
  instead.
- **The Agents view** (`agents` in the search) lists every agent on every
  Machine by Project, with Needs you / Working / Done filters. Each row shows
  the task, step 3 of 8, what the agent says is left ("claude says ~12 m"),
  Sentinal's own estimate ("about 15 m at this pace") and time on task. The
  island shows a progress ring for a working agent.
- What an agent says wears a solid outline; what Sentinal measures has no
  marker; guesses are dashed. A report never ends a terminal, answers a
  question or sends a notification on its own.
- **Sandbox terminals:** `sentinal watch --sandbox` gives a job its own
  private folder, kept afterwards for you to review. It still runs as you:
  a separate place to work, not a security boundary.
- `sentinal agent-skill` prints instructions an agent can follow, and
  `sentinal agent-skill --install` adds them to a project's `AGENTS.md` or
  `CLAUDE.md` after showing you the change and asking.
- `sentinal agent-guide`, and `sentinal watch --detach` for agents without
  a terminal.

### Progress without an adapter
- Programs that print `task 3/50`, `[4/10]` or a tqdm bar show progress.
  Programs can print `::sentinal progress current=3 total=50` and
  `::sentinal metric name=loss value=0.81`.

### Machines
- One daemon install per Machine: the control refuses a second install
  claiming a live Machine and warns you, and repairs gaps in a worker's
  history.
- The Settings tab for agent tokens is now called **Agent access**.

## Fixed
- Prompts without a newline (`Publish? [y/N] `) now become WAITING.
- The same question asked again after an answer is reported again.
- "Agent finished" notifications arrive; question and progress notifications
  no longer repeat too often.
- Bash terminals record the command as typed.
- A long worker history can resync a fresh control.
- A killed terminal's command finishes and every viewer sees it.
- A Ctrl+J in pasted text no longer detaches.
- History, Save recipe and Diagnostics layout; charts with one sample.
- The sign-in lock message matches the configured attempts.

## For developers

Protocol changes. All are additive, so `PROTOCOL_VERSION` stays 1; fixtures
were changed on purpose:

- `RESTORE_SESSION`, `DELETE_SESSION`, `SESSIONS_DELETED`, tombstones
- Heartbeat `instance_id`, `build_commit`; `INSTANCE_CONFLICT`
- `CodingAgent::VIBE`, `ANTIGRAVITY`; prompt option labels up to 160 characters
- `METRIC_REPORTED` Event kind
- Local `AGENT_STATE` with optional `task`, `step`, `steps`, `eta_secs`;
  `agent_state` and `sandbox` on Sessions (never stored)
- `CREATE_SESSION.sandbox` (WATCH only)
- Store migrations 014 (`id_floors`) and 015 (`machine_instances`)
