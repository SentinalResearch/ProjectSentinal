# Sentinal 2.12.0

*Draft, 2026-11-24. Not released; the owner ships it with `just ship 2.12.0`.*

Terminals that survive a daemon restart or update, one correct screen on
every device, and `sentinal watch` to pick up any terminal from anywhere.

## Before you update

1. **Back up each Machine first.** Rolling back to 2.11.0 after 2.12.0 has
   run means restoring this backup onto a fresh 2.11.0 install.

   ```sh
   sentinal backup create
   ```

2. **The control does not offer this update by itself.** 2.11.0 controls only
   accept a release that has an Intel Mac build, and 2.12.0 has none (Intel
   Macs are no longer supported). Install 2.12.0 on the control once by hand,
   with the same steps as a new control (`docs/PILOT.md` §2, "Install the
   control"). The installer keeps the existing config and data, so the
   workers and your password stay; open browsers have to sign in again, as
   after every daemon restart. From then on the control updates itself as
   before.
3. **Then update the workers from the dashboard,** as usual. Workers have no
   such check, so the 2.12.0 control's update button works for them.
4. **This update still ends live terminals, one last time.** The 2.11.0
   daemon being replaced does not have keepers. Terminals started under
   2.12.0 survive the next restart or update.

## New

### Terminals survive restarts and updates
- Every terminal is held by its own small keeper process. When `sentinald`
  crashes, restarts or updates, the program keeps running; the new daemon
  takes it back and the screen, history and running Command carry on.
- Output printed while no daemon was running is kept (the last 1 MiB) and
  shown once the daemon is back.
- Only this daemon can take a keeper back: a private socket, the same user,
  and a secret that never leaves the Machine. Anything it cannot verify is
  left alone and that terminal is marked interrupted, with the reason.
- Updates no longer warn that they will end terminals a keeper holds.
- `SENTINAL_KEEPERS=0` turns keepers off. If a keeper cannot start, the
  terminal runs inside the daemon as before.

### One screen on every device
- The daemon keeps the one true screen (new terminal engine,
  libghostty-vt). Every viewer starts from a whole screen, never in the
  middle of an escape sequence.
- One size per terminal, set by the device you last typed in or focused.
  Others show the same screen scaled to fit, with "Sized for another
  device · Use this size".
- Answer buttons pick the menu row from the current screen and refuse if
  the question changed.
- Emoji and wide characters line up; resizing is smooth; the CLI follows
  window size changes and always restores your terminal on detach.

### Pick up anywhere
- `sentinal watch` with no Command lists live terminals on every Machine,
  the ones waiting for you first, and attaches; `sentinal watch NAME`,
  `--last`, `--machine`. `--new` starts a fresh shell (the old bare
  `watch`).
- `sentinal login` signs the terminal in as you, so it can reach terminals on
  other Machines through the control.
- Picking up shows the history, not only the visible screen.

### Runs, estimates and agents
- Groups for runs (`--group run/model/job`): one card per run with its
  parts, progress, time left and failures.
- `watch --exit`: a job's terminal ends with the job's exit code.
- Time left for any running Command, from its progress or from earlier
  runs of the same command.
- Claude Code terminals as a chat, read from Claude Code's own file
  (desktop; `sentinal agent-chat setup`).

## Fixed
- Agent Events, multi-byte training lines, server ports, health after an
  answered question, bursts of warnings, and repeated questions (T0).
- A second `sentinald` started by mistake no longer disturbs the running one.
- An offline Machine's live terminals show DISCONNECTED, not IDLE.
- Session RAM, GPU pressure and adopted-process times (F1–F4).

## Not supported any more
- **Intel Macs.** No `x86_64-apple-darwin` build; installers refuse Intel
  Macs.

## For developers

All protocol changes are additive; `PROTOCOL_VERSION` stays 1. Fixtures were
changed on purpose:

- `ATTACH.history`, `ATTACH.cols`, `rows`, `mode`; `VIEWER_STATE`,
  `ANSWER_PROMPT`, `SESSION_SIZE` (sent only to viewers that sent a size);
  `ViewerMode`
- `WAITING_FOR_INPUT.marked`
- `Session.kept`; agent chat entries, `GET_CHAT`, `CHAT`, local
  `AGENT_TRANSCRIPT`; `SET_GROUP`; `Session.estimate` (never stored)
- Store migration 016 (`session_keepers`); Session logs as independent zstd
  frames with `sessions/<id>.offset`
- New `daemon.toml` key `attach_history_lines` (default 2000)
- `sentinald keeper`, `sentinald keeper stop-all`; the launchd plist gains
  `AbandonProcessGroup`; on Linux each keeper gets its own systemd scope
- Linux release builds need Zig 0.17.1 (`scripts/fetch-terminal-engine.sh`)

Reports: `docs/progress/terminal-upgrade.md`.
